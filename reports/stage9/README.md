# Финальная приёмка Food Delivery

Проверки выполнялись 11.10.2026 на локальном Docker Desktop. Исторические
нагрузочные отчёты этапа 8 сохранены отдельно и не заменены короткими проверками.

## Воспроизведение

Из корня `infrastructure`:

```bash
make up
make grafana-up
make logs-up
make acceptance
```

Интеграционные тесты уведомлений, включая аварийное окно, запускаются из корня
`notifications-service`: `go run ./cmd/ci-integration`.
Обычные проверки каждого репозитория: `bash scripts/ci-check.sh`.

Сценарии отказов намеренно меняют доступность зависимостей и оставляют учебные
заказы в стенде. Тесты с временными БД и Kafka-топиками удаляют собственные ресурсы.
Для SIGKILL инструмента автоматический cleanup невозможен; ручное восстановление
описано в основном README.

## Ограничения доказательств

- Все результаты локальные. GitHub Actions workflow обновлён, но удалённый run
  не выполнялся: Git remotes у репозиториев не настроены.
- Стенд поднят по README с существующими volumes. Установка всей системы
  одновременно на полностью пустых volumes отдельно не выполнялась.
- Состояние GUI, data view, сохранённые поиски и результаты поиска проверяются
  через HTTP/API. Автоматизация браузера Kibana дважды завершилась таймаутом;
  визуальная проверка страницы не заявляется.
- ILM/retention настроены и проверены через API. Семидневное ожидание удаления
  не проводилось; это асинхронное удаление индексов, а не точный TTL документа.
- Проверки Kafka выполняются на одном брокере с RF=1; высокой доступности брокера,
  PostgreSQL, Redis и самого балансировщика в этом проекте нет.

## ClickHouse

Условный блок выполнен: ClickHouse 26.8.24.9, отдельный profile `analytics`,
Kafka Engine → materialized view → MergeTree и consumer group `analytics-v1`.
`analytics.json` подтверждает: одна доставка до повтора, две после, один заказ
в агрегате и прежняя сумма 44900 копеек; после рестарта результат тот же.
Заказ, созданный при остановленном ClickHouse, получил уведомление сразу и попал
в аналитику после запуска. На момент проверки lag всех трёх партиций равен нулю.
Три SQL-запроса выполнены; /play отвечает HTML. Сумма относится к созданным,
а не оплаченным заказам. Нет репликации, аналитического DLQ или TTL raw-таблицы.

Дополнительное воспроизведение: `make analytics-up`, `make check-analytics`,
`make analytics-query`. Новый ClickHouse был поднят с пустым собственным volume.
